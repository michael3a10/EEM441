\experimentheader{9}{Experiment 9}{IIoT Monitoring \& Alarm Visualization for a PLC-Controlled Machine}{IoT Lab}

\begin{objectives}
  \begin{enumerate}
    \item To understand the role of each layer in an IIoT monitoring pipeline: PLC, SCADA, database, and dashboard.
    \item To configure communication between a Siemens S7-1200 PLC and Advantech WebAccess/SCADA.
    \item To bridge SCADA tag data to a PostgreSQL database via ODBC, so that history is available outside WebAccess.
    \item To design a web-based IIoT dashboard displaying real-time sensor status and visual alarms, using the WISE-IoTSuite/Dashboard application.
    \item To demonstrate a complete monitoring pipeline, from a physical sensor to a live dashboard panel.
  \end{enumerate}
\end{objectives}

\begin{equipment}
  \begin{itemize}
    \item MTA SkillLab i-Factory kit: conveyor sorting machine with Siemens SIMATIC S7-1200 CPU 1212C AC/DC/Rly, fitted with vibration, laser-distance, temperature/humidity, and part-counting sensors
    \item PC/laptop with Advantech WebAccess/SCADA V9.x installed (Project Node and SCADA Node)
    \item PostgreSQL, with the \texttt{psqlodbc} (x86) ODBC driver and pgAdmin4 installed
    \item ODBC Data Source Administrator (32-bit) --- WebAccess only supports 32-bit ODBC connections
    \item Ethernet cable and a configured local network connection between the PC and the PLC
  \end{itemize}
\end{equipment}
\newpage

\begin{introduction}
  Industrial IoT (IIoT) monitoring bridges field-level operational technology (OT) --- sensors, actuators, and the PLC that controls them --- with IT-side visualization and analytics. This experiment builds that bridge one layer at a time, using the same i-Factory conveyor rig and WebAccess/SCADA software introduced in Experiment 5.
  \vspace*{1.5em}

  \textbf{Communication protocols used at each layer} (Table~\ref{tab:exp9-protocols}): Modbus links the sensors to the PLC; TCP/IP (or OPC UA) links the PLC to WebAccess/SCADA; and ODBC links WebAccess/SCADA to the PostgreSQL database that the Dashboard ultimately reads from.
  \vspace*{1.5em}

  The full pipeline is shown in Figure~\ref{fig:exp9-pipeline}. Each stage depends on the one before it: a tag with no PLC communication shows no data; a tag with communication but no \textbf{Log Data} setting never reaches the database; and a database with no rows has nothing for the Dashboard to display. Troubleshooting this experiment usually means working backward through this chain to find where data stops flowing.
\end{introduction}

\begin{labsection}{Sensor Assignment}{}
  Each lab group is assigned one primary sensor/parameter to monitor for this experiment. Working with a distinct analog or discrete signal per group ensures each team independently validates its own signal path (PLC addressing, tag configuration, alarm thresholds, and dashboard binding) rather than inheriting settings tuned for a different sensor type.

  Refer to Table~\ref{tab:exp9-groups} for your group's assigned sensor, its PLC DB address, and the suggested tag prefix to use in WebAccess/SCADA.

\begin{procedure}

  \textbf{Activity 1 --- Create the SCADA project and connect to the PLC}\vspace{2pt}

  \textit{Objective: create a WebAccess/SCADA project and bring your assigned sensor in as a live tag.}

  \begin{enumerate}
    \item Open a web browser and navigate to \texttt{127.0.0.1} (or \texttt{localhost}) to reach the WebAccess/SCADA landing page. Select \textbf{Project Management} from the \textbf{Platform} drop-down and log in (default account \texttt{admin}, no password).
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.75\linewidth]{figures/WebAccess_login_project_management.png}
            \captionof{figure}{WebAccess/SCADA sign-in, with Project Management selected.}
            \label{fig:exp9-login}
          \end{boxedfigure}
    \item Create a new project: enter a \textbf{Project Name} and \textbf{Description}, set the \textbf{Project Node IP Address} (\texttt{127.0.0.1} for local), and keep the default \textbf{Primary TCP Port} (4592) and \textbf{HTTP Port} (80) unless instructed otherwise.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=\linewidth]{figures/WebAccess_add_new_project.png}
            \captionof{figure}{Create New Project form.}
            \label{fig:exp9-newproject}
          \end{boxedfigure}
    \item Create a \textbf{SCADA Node}: select your Project Node, click \textbf{+}, choose \textbf{New Node}, and fill in the Primary Node Name, TCP Ports, Node Timeout, and SCADA Node IP Address.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=\linewidth]{figures/WebAccess_insert_SCADA_node.png}
            \captionof{figure}{Create New SCADA Node form.}
            \label{fig:exp9-newnode}
          \end{boxedfigure}
    \item Add a \textbf{Communication Port}: choose \textbf{TCP/IP} as the interface, and configure the Scan Time (e.g.\ 1000\,ms) and Auto-Recover Time.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.5\linewidth]{figures/WebAccess_SCADA_node_COMPORT_Settings.png}
            \captionof{figure}{Communication port (Comport) settings.}
            \label{fig:exp9-comport}
          \end{boxedfigure}
    \item Add a \textbf{Device} on that Comport: set Device Type to \texttt{SiemS7}, enter the PLC's IP address and port (\texttt{102}), and set the TSAP in hex for an S7-1200 (\texttt{01.01}).
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.55\linewidth]{figures/WebAccess_insert_device_settings_1.png}
            \captionof{figure}{Add Device form (S7-1200).}
            \label{fig:exp9-adddevice}
          \end{boxedfigure}
    \item Create an IO Tag for your assigned sensor, using the prefix from Table~\ref{tab:exp9-groups} (e.g.\ \texttt{G1\_Temp}), and a second discrete tag for Start, Stop, or Emergency Stop. Set the Address, Data Type, and Conversion Code to match your PLC DB offset.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/WebAccess_insert_analog_tag_temp_sensor.png}
            \captionof{figure}{Insert IO Tag form (analog sensor example).}
            \label{fig:exp9-inserttag}
          \end{boxedfigure}
    \item Start the SCADA Node's Kernel, open \textbf{ViewDAQ}, and confirm both tags are updating with live values that reflect what is actually happening on the machine.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/WebAccess_kernel_viewdaq.png}
            \captionof{figure}{Kernel running, viewed in ViewDAQ.}
            \label{fig:exp9-viewdaq}
          \end{boxedfigure}
  \end{enumerate}
  \vspace*{1.5em}

  \textbf{Activity 2 --- Configure an alarm}\vspace{2pt}

  \textit{Objective: enable alarming on your assigned sensor, so threshold breaches are visible in both SCADA and, later, the dashboard.}

  \begin{enumerate}
    \item Open your analog sensor tag's configuration and enable a non-zero alarm priority (High, High-High, Low, or Low-Low, as appropriate to your sensor).
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/WebAccess_SCADA_TempEdit_alarm_settings.png}
            \captionof{figure}{Alarm priority configuration.}
            \label{fig:exp9-alarmconfig}
          \end{boxedfigure}
    \item Enable state alarming on your discrete tag (e.g.\ alarm when Emergency Stop becomes active).
    \item In \textbf{ViewDAQ}, trigger a manual threshold breach (e.g.\ briefly block the sensor's path, or press the Emergency Stop) and confirm the alarm appears in the SCADA \textbf{Alarm Summary}.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/WebAccess_SCADA_TempEdit_real-time_trend.png}
            \captionof{figure}{Alarm triggered, viewed on the real-time trend.}
            \label{fig:exp9-alarmtrend}
          \end{boxedfigure}
  \end{enumerate}
  \vspace*{1.5em}

  \textbf{Activity 3 --- Bridge SCADA to PostgreSQL via ODBC}\vspace{2pt}

  \textit{Objective: connect WebAccess to a PostgreSQL database, and enable logging so your tag's history is written there.}

  \begin{enumerate}
    \item Confirm with your instructor that PostgreSQL, the \texttt{psqlodbc} (x86) driver, and pgAdmin4 are already installed --- this experiment assumes they exist; installing them from scratch is outside the scope of this lab.
    \item In pgAdmin, create a connection to the PostgreSQL server (Host \texttt{127.0.0.1}, Port \texttt{5436}, default credentials provided by your instructor), then create a new database for this experiment.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/pgAdmin_addServer.png}
            \captionof{figure}{pgAdmin: registering the PostgreSQL server.}
            \label{fig:exp9-pgadminserver}
          \end{boxedfigure}\newpage
    \item Open \textbf{ODBC Data Source Administrator (32-bit)}, switch to the \textbf{System DSN} tab, click \textbf{Add}, and select \textbf{PostgreSQL Unicode}. Fill in the Data Source name, Database, Server, Port, Username, and Password to match the database you just created.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/ODBC_DSN_PostgreSQL.png}
            \captionof{figure}{ODBC Data Source Administrator (32-bit).}
            \label{fig:exp9-odbcadmin}
          \end{boxedfigure}
    \item Back in WebAccess, open the project's \textbf{Setting} menu $\to$ \textbf{ODBC data record source}, and insert a new ODBC entry: a numeric Log Data Source ID, the DSN name from the previous step, and matching login credentials. Test the connection.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/ODBC_DSN_PostgreSQL_Settings.png}
            \captionof{figure}{WebAccess ODBC data record source.}
            \label{fig:exp9-odbcrecordsource}
          \end{boxedfigure}
    \item On your SCADA Node, enable \textbf{Data Log to ODBC} (\textbf{Edit Node} $\to$ \textbf{Data Log}). Then, on each tag you want logged, enable \textbf{Log Data} and set the \textbf{Data Log Interval} to \texttt{0} (record by deadband) to avoid missed samples.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=\linewidth]{figures/WebAccess_ODBC_DataLog.png}
            \captionof{figure}{SCADA Node Edit Node: Data Log tab.}
            \label{fig:exp9-nodedatalog}
          \end{boxedfigure}
    \item Download the project to the SCADA Node, then confirm in pgAdmin that rows are appearing in the corresponding log table (e.g.\ \texttt{bwanalogtable} for analog tags).
          \begin{boxedfigure}
            \centering
            \includegraphics[width=\linewidth]{figures/pgAdmin_Table_query_result.png}
            \captionof{figure}{pgAdmin: logged rows in the analog log table.}
            \label{fig:exp9-pgadminresult}
          \end{boxedfigure}
  \end{enumerate}
  \newpage

  \textbf{Activity 4 --- Build a dashboard}\vspace{2pt}

  \textit{Objective: visualize your assigned sensor and its alarm state on a WISE-IoTSuite/Dashboard panel.}

  \begin{enumerate}
    \item From the WebAccess landing page, select \textbf{Dashboard} from the \textbf{Platform} drop-down instead of Project Management.
    \item In the Dashboard app, open \textbf{Configuration} $\to$ \textbf{Data Sources} $\to$ \textbf{Add data source}, choose \textbf{PostgreSQL}, and enter the same connection details used for the ODBC bridge in Activity 3. Click \textbf{Save \& Test} and confirm a successful connection.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=\linewidth]{figures/WIISE_PAAS_add_data_source_postgresql.png}
            \captionof{figure}{Dashboard: Add PostgreSQL data source.}
            \label{fig:exp9-dashdatasource}
          \end{boxedfigure}
    \item Create a \textbf{new Dashboard}. Add at least two panels:
          \begin{itemize}
            \item a \textbf{Singlestat} or \textbf{Graph} panel bound to your assigned analog sensor tag, and
            \item an \textbf{Alert}-enabled panel (or an Alert list) showing the current state of your alarm from Activity 2.
          \end{itemize}
          \begin{boxedfigure}
            \centering
            \includegraphics[width=\linewidth]{figures/WIISE_PAAS_create_dashboard.png}
            \captionof{figure}{Dashboard panel query binding.}
            \label{fig:exp9-panelquery}
          \end{boxedfigure}
    \item For each panel, select your PostgreSQL data source and the query/tag that corresponds to your assigned sensor.
    \item Label your dashboard clearly with your group number, so it is identifiable in your submitted report.
    \item With the machine running, confirm each panel updates live, and that triggering your alarm condition changes the alert panel's state.
          \begin{boxedfigure}
            \centering
            \includegraphics[width=0.8\linewidth]{figures/WIISE_PAAS_alert.png}
            \captionof{figure}{Finished dashboard example.}
            \label{fig:exp9-finisheddashboard}
          \end{boxedfigure}
  \end{enumerate}

\end{procedure}

\begin{labsection}{Appendix: Troubleshooting}{}
  This experiment's pipeline has four layers (Table~\ref{tab:exp9-protocols}), and almost every symptom traces back to exactly one of them. Work backward from where the data visibly stops:
  \begin{enumerate}
    \item If the dashboard panel is blank, check whether the database has rows; if not, check whether SCADA shows a live value; if not, check the PLC connection.
    \item If the database has no rows, check whether SCADA is configured to log data; if not, check whether the SCADA Node is running; if not, check the ODBC connection.
    \item If SCADA shows no live value, check whether the tag is configured correctly; if not, check whether the Comport and Device are configured correctly; if not, check the PLC connection.
  \end{enumerate}
\end{labsection}
